# Cellular co-op: path from transport probe to gameplay

This is an implementation plan, not a claim of playable co-op. The `cellular-transport-probe` feature exchanges actor-free shadow state; `src/coop.rs::build` still returns early for cellular worlds. Do not remove that guard for ordinary players until the gates below pass on the real map and mobile hardware.

## Existing seam and why the app cannot call it yet

`src/player.rs::apply_requests` writes the local crab's `Controls`, and `simulate` advances `Sim::tick()` at 120 Hz, up to 0.25 seconds of catch-up per rendered frame. Cellular material moves every fourth tick. `src/coop.rs::take_in` runs in the input set and `send_out` after simulation; the current co-op model sends remote crab state for display, not ordered input for a shared terrain step. Those updates cannot establish that a remote force belongs to the exact tick and terrain the host is stepping.

The guarded methods in `crates/sim/src/world.rs` and `net/cell_join/lockstep.rs` prove a much smaller case: fresh tick-zero sessions, one local crab on each side, at most one remote crab, no enemies or recording, supported horizontal walking and limited guest horizontal digging. Jumping, upward velocity, most actions, many body interactions, and some active-window changes reject. `Guest::apply` checks the exact guest force, host connection, epoch, material tick and digest before allowing its terrain step; it is not a general client prediction or correction system. Calling ordinary `Sim::tick()` even between material ticks bypasses those checks. A real populated game normally fails the current guards immediately.

## First real-transport milestone: disposable two-player sandbox

1. Add an explicit developer-only mode with two actual local crabs in separate, disposable test-level Sims and no enemies, recorder, persistent writes, migration or live cellular game state. Keep the existing cellular co-op and save UI disabled. Negotiate an application version, static level/tuning identity, protocol version and a fresh session epoch; reject incompatible worlds, duplicate player claims and a connection that is not the selected host or the one bound to the guest. The existing `Peer` pairs player ID with actual Matchbox connection ID; use it on **every** input, checkpoint, frame and acknowledgement, not just the initial handshake. Never use a claimed player ID as authority.
2. Install a bounded host checkpoint in the guest's temporary Sim before spawning or enabling either actor. Explicitly agree on game tick, terrain tick, phase, initial positions and controls. Current `begin_guest_shared_walking` needs fresh tick zero; supporting a resumed live world requires a separately tested clock/actor restoration contract. Abort on phase, level, clock or checkpoint mismatch. Dropping the session and disconnecting must restore the real guest's private terrain via its existing `OwnWorld` lifecycle; no network data may overwrite a solo save.
3. Define a bounded, versioned **input** message distinct from an authoritative terrain `Frame`: epoch, game tick, sequence, player and the complete control state including one-shot press edges. Reject non-finite/out-of-range input, duplicate IDs, forged connections, duplicate/stale/out-of-window sequence numbers and gaps. Allow only the currently proved walking/guest-dig subset; unsupported input pauses before either Sim, clock, terrain, outbox or press edge is mutated. Cap per-peer pending bytes, packets and tick horizon; disconnect, host change, timeout, queue overflow and corrupt input invalidate the epoch and clear its buffers.
4. Replace the unconditional `simulate` path **only inside the disposable developer mode** with an explicit barrier. At each 30 Hz material boundary, both sides must be at the same 120 Hz tick with the same accepted inputs. Host validates the source-bound guest proposal against the guest actor state for that tick, derives/validates both forces, then calls the transactional guarded host step exactly once. It sends the ordered terrain frame; the guest applies it to the same pre-step terrain, verifies the digest, and acknowledges. Both sides may advance the three guarded non-material ticks only in the agreed order. Any failure after partial work must roll back the entire affected tick, including actor state, terrain, events and outbound messages, or abandon the disposable session; the current guest terrain step plus subsequent independent actor ticks do not by themselves provide that transaction. Freeze the accumulator while waiting and do not convert network delay into an unbounded catch-up burst.
5. Do not trust a guest-supplied `HostPlayerForce` merely because its `PlayerId` is correct. Today's FakeLink test forwards the guest's computed force; it does not validate position, dimensions, velocity, grounded state or action against an authoritative guest actor on the host. Either make the host simulate that actor from the tick-stamped input, or specify and test a bounded, authoritative state/force validation and reconciliation contract. The ordinary `Msg::Crab` interpolation stream cannot be the deterministic input to this step.
6. Exercise this exact app scheduling and real Matchbox transport in two isolated Chrome instances: both players walk and the guest digs across sand, mud and pebbles, including overlapping and separated bodies. Compare each terrain frame and authoritative actor state to a single reference run, preserve mass, and inject reordered, duplicate, delayed, lost, forged and oversized packets. Verify waiting, unsupported input on *each* of the four game ticks, failed sends, digest divergence, disconnect and reconnect leave no partially applied tick or altered private world. Run an additional native/Wasm determinism check; a same-process FakeLink result does not establish cross-platform equality.

This milestone is a correctness harness, not a playable release. With stop-and-wait at each material frame, network round trips directly throttle movement; the local probe's one-packet exchange took roughly 148 ms including game-loop scheduling. An eight-fragment checkpoint window improved join throughput, but does not solve 30 Hz live latency. The current host method clones a full `Sim`, the guest digest path clones and serializes the world, and active-window handling still imposes substantial per-step work. Measure CPU, frame time, queued bytes and peak total memory on actual target phones before extending scope. The developer ingress cap covers tagged probe payload only; normal Matchbox traffic, WebRTC/browser buffers, checkpoint assembly and decompression remain separate unbounded or large-memory paths. Full-world checkpoint joins are not a scalable correction strategy.

## From guarded sandbox to actual game

- **Actor authority and input:** choose a single authoritative owner per player and make remote actor state reproducible from tick-stamped controls and world state. Define how inventory, damage, interaction, animation events and one-shot controls are acknowledged and deduplicated. Preserve existing ordinary co-op semantics until the cellular path has equivalent tests.
- **Prediction and reconciliation:** keep an explicitly bounded input/state history. Predict only cases known to be reversible; attach epochs and authoritative tick/hash to confirmations. On mismatch, restore an authoritative actor and affected terrain snapshot, replay accepted local inputs and smooth presentation separately. When rollback history, chunk correction, hashes or memory budgets are unavailable, pause safely and request a bounded resynchronization or leave to the restored solo world; never silently continue divergent simulations. A malformed, stale or forged packet must not trigger arbitrary rollback or replace private state.
- **Creatures and environmental forces:** existing co-op distributes enemy ownership; the cellular path must agree on which simulation owns each creature at a given tick and propagate the resulting deterministic movement, attacks, wakes, digging, deaths and ownership changes once, in a stable order. Define handover and duplicate/late event rules and prove a moray/shrimp encounter, shared damage and substrate disturbance in a two-player reference test. Until an actor, kelp interaction, current source or environmental effect has an exact shared representation, pause or reject the session rather than omit its terrain forces.
- **World scale, joining and failure:** replace whole-world snapshot copying/digesting with validated chunk-scoped transfer and bounded, backpressured decode; retain the guest's own world across join, host migration, reconnect and cancellation. Define epoch changes and authoritative chunk repair, then test dropped/reordered chunks, host departure during transfer, mixed-host packets and memory limits. Ensure separate interest windows and their boundaries preserve deterministic ordering, particle conservation and pebble atomicity.
- **Release gate:** lift the cellular `build` guard only after actual app tests cover supported controls, NPCs, full-map saves/replay, migration, mobile networking, browser backgrounding, normal/offline recovery, and sustained CPU/memory budgets. A single developer probe or taste test is not evidence of feature parity.

## Host-owned actor input prototype

`net/cell_join/input.rs` adds an isolated, unwired next slice: a host owns both its authoritative Sim and a guest-actor shadow initialized from trusted matching state. It accepts only a connection-bound, tick/sequence/epoch-stamped horizontal walk/dig input or a straight-down dig command, plus separate local host dig controls, derives the guest force from the host-owned shadow, advances the host terrain and independently reproduces that terrain in the shadow before committing. Both Sims are cloned so failed material or off-material steps leave actor state, terrain, controls and outboxes unchanged; a gap, disconnect, invalid value, wrong epoch or unsupported step pauses. Stale/duplicate and wrong-peer/player inputs are rejected. A real two-Sim/FakeLink test compares the guest actor and material-step terrain, checks sand/mud and pebble conservation, compares dig resistance and local terrain to solo references, and covers rollback after host work has begun. This is only a test-level walking and horizontal/straight-down dig fixture with no pickups or spawned creatures; it rejects shelter transitions and non-crab outbox effects. The constructor requires trusted host-created initial actor state, transport binding is still the caller's responsibility, it clones full Sims and hashes/replays full terrain, and its ordinary material-only mode does not support upward digging, jumping, other action buttons, enemies, loaded worlds, prediction, live-loop scheduling or recovery. The network message is ignored by ordinary gameplay. Nothing here authorizes enabling cellular co-op.

Horizontal host digging preserves both body reservations. When both players dig, the host scoop is applied first; if it would change the guest’s pre-step dig resistance, the step is rejected rather than silently using a different ordering. In one local release-mode desktop fixture, median material ticks were 34.89 ms with host digging versus 32.07 ms walking (nine samples each); intervening ticks were about 0.61 ms. This includes full-Sim clones, replay and hashing, and excludes rendering/networking. It is not a phone measurement and is not sufficient for a 30 Hz production budget. Straight-down digging now applies the protected two-body pebble sweep before its cavity push. A rock-blocked cavity keeps a successful sweep, while unsupported or partially cleared non-rock cavities fail transactionally. A separate upward-only sandbox mode sends an authoritative operation on every 120 Hz game tick, including ticks without a material step. It is locked to that mode for the session; horizontal/downward actions and release while still moving upward fail closed. Both player bodies are reserved, host effects precede guest effects, and terrain plus the guest actor commit transactionally. It remains disconnected from the live game and still requires trusted host initialization, real transport integration, latency handling and cross-platform testing.

For a separate open-sand downward fixture on the same local desktop, median material ticks were 40.08 ms for guest digging and 37.42 ms for host digging (six samples each), with intervening ticks about 0.61 ms. The timings include whole-Sim clones, terrain replay and hashing, exclude rendering and networking, and do not represent phone performance.

In one local desktop release-mode upward guest fixture, median material operations took 36.34 ms (six samples) and off-material operations took 15.85 ms (18 samples), including full clones, independent terrain replay and a full checkpoint digest per tick. These figures exclude networking and rendering, are not phone measurements, and exceed both 30 Hz and 120 Hz budgets.

A separate off-material component profile on that desktop (nine samples per component) measured medians of 12.796 ms for the full checkpoint digest, 1.849 ms for the host terrain operation, 1.797 ms for shadow replay, 0.259 ms for cloning both Sims, about 0.24 ms for each full-world equality check, and 0.019 ms for both actor ticks. These independent component medians are not a summed end-to-end benchmark.

## Experimental incremental verification: semantics and costs

A test-only dirty-state oracle compares the five active cell fields, archived chunks, and the exact serialized representation of every remaining checkpoint field. Separate test-only hooks mark writes in the restricted upward sandbox; comparisons cover sand, mud, whole pebbles, rock blockage, streaming away and back, and both material and off-material ticks. On one sparse off-material scoop two of 60 active tiles changed; in the opening diffusion fixture 53 of 60 changed. These fixtures do not prove that every possible or future mutation is instrumented.

A test-only FakeLink sidecar runs the existing host and guest full-digest protocol and independently checks traced changes against the exhaustive oracle. It is diagnostic: it runs after the normal guest transaction, so a sidecar failure cannot undo that already committed transaction. A corrupted normal frame is rejected before guest commit. In one desktop release run, full host-plus-guest FakeLink ticks had medians of 16.46 ms for the existing verifier and 35.02 ms with the additional audited sidecar (24 mixed-phase ticks per mode). The sidecar's two retained World clones contained at least 6,012,876 bytes of vector payload, excluding tree nodes, allocator overhead, temporary copies, rendering and networking outside FakeLink. This duplication is not a production optimization or a phone estimate.

A candidate nonduplicated design would start from an authenticated, fully matched checkpoint and derive a bounded, ordered journal from the same mutation primitives that commit each tick: all five material/flow fields, aggregate state, particles, crab reservations, clocks and world metadata, plus chunk activation, sleeping changes and origin moves. Host and guest independently compute canonical journal entries for the same source-bound epoch and tick; verify the entries and resulting marked chunk/metadata fingerprints before atomically committing terrain, both actors and outboxes. Reject unknown mutation paths, capacity overflow, bad ordering, unsupported effects or invalid inputs before commit. A full checkpoint digest on a bounded schedule detects unrelated state drift, and recovery must restore the last fully verified terrain **and actor/event state**, discard later outputs and replay ordered inputs or resynchronize. Bind journals and checkpoints to the actual transport connection; existing FNV hashes detect accidental divergence but do not authenticate a peer or protect against adversarial collisions.

A periodic checkpoint alone changes failure semantics: an omitted mark can be accepted until the next full check, after which previously committed frames must be rewound. The current test model demonstrates that delay; its full-world oracle guard catches omitted marks immediately but costs a full scan and snapshot. Replacing the current per-tick full digest therefore requires either a complete and independently enforced mutation journal or an explicit, tested speculative rollback contract; test coverage alone cannot establish completeness. The present model does not implement actor/event rollback, packet encoding, real transport, bounded journal memory, host migration or an optimized paired tick. No alternate end-to-end timing has been measured, and the regular co-op guard and full digest remain in place.

A narrower test-only journal now records actual ordered material swaps as they happen in a chunk scoop, with prior-value checks and atomic replay. It caps the log at 65,536 events, including material swaps, local flow writes, silt appends and supported pebble pushes. An additional full-checkpoint digest is required before replay commits: omitting a final event can evade its old-value checks alone. It is not a complete world journal: it excludes streaming, actors, arbitrary simulation steps and other pebble movement; it is not connected to the upward network loop. The normal full digest remains required. In one 15-swap desktop fixture, 20 interleaved release samples had median chunk-only times of 1.228 ms for the scoop, 1.210 ms with recording and 0.093 ms to replay; these noisy measurements exclude whole-world conversion, full verification, actors, transport and rendering and do not establish a recording speedup or usable paired-tick performance.

In an isolated FakeLink test, one pebble-plus-wake journal encoded to 6,351 bytes and required two existing 4,096-byte-limited messages. A test-only wrapper caps reassembly at 64 KiB and decoding at 4,096 fixed-size events; it checks selected peer and transfer identity, rejects malformed, oversized, conflicting and disconnected transfers, and applies decoded chunk events only after the existing full digest matches. This uses caller-supplied FakeLink identities and does not establish real WebRTC authentication, actor synchronization, live installation, ACK pacing or production memory limits. If that one journal size were sent at every 120 Hz tick, payload alone would be 762,120 bytes/s (about 6.10 Mbit/s) per guest, excluding envelopes, acknowledgements, retransmission, inputs and other data. That is a repeated-fixture scenario, not a measured average. The test delivers fragments together at zero simulated delay; there is no measured RTT or latency behavior, and reliable per-tick stop-and-wait must not be assumed viable.

The disposable WebRTC actor probe can optionally send four predeclared upward inputs in one bounded batch; its default remains stop-and-wait. In two local, voice-off Chrome comparisons on one desktop, the complete four-tick actor phase took 0.394/0.416 seconds pipelined and 0.675/0.690 seconds stop-and-wait. It remains automated, uses isolated test Sims, and neither accepts live controls nor proves prediction or phone/WAN performance. Two additional profiled stop-and-wait runs measured four host callbacks totaling 69.9/69.9 ms (maximum 41.4/41.5 ms) and guest callbacks totaling 54.5/54.0 ms (maximum 31.9/31.2 ms). A separate extra full digest took 6.5 ms host and 6.4 ms guest in each run. The profiled actor phase took 0.848/1.443 seconds and includes both extra digests, protocol delivery and browser scheduling; those remaining costs are not separately attributed. Chrome reported nominated ICE candidate-pair RTT of 0–1 ms on loopback. That statistic is not application-message latency, and the harness captures the last peer connection only; results apply to this two-peer, voice-off test.
