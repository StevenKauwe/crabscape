# Cellular co-op: path from transport probe to gameplay

This is an implementation plan, not a claim of playable co-op. The `cellular-transport-probe` feature exchanges actor-free shadow state; `src/coop.rs::build` still returns early for cellular worlds. Do not remove that guard for ordinary players until the gates below pass on the real map and mobile hardware.

## Existing seam and why the app cannot call it yet

`src/player.rs::apply_requests` writes the local crab's `Controls`, and `simulate` advances `Sim::tick()` at 120 Hz, up to 0.25 seconds of catch-up per rendered frame. Cellular material moves every fourth tick. `src/coop.rs::take_in` runs in the input set and `send_out` after simulation; the current co-op model sends remote crab state for display, not ordered input for a shared terrain step. Those updates cannot establish that a remote force belongs to the exact tick and terrain the host is stepping.

The guarded methods in `crates/sim/src/world.rs` and `net/cell_join/lockstep.rs` prove a much smaller case: fresh tick-zero sessions, one local crab on each side, at most one remote crab, no enemies or recording, supported horizontal walking and limited guest horizontal digging. Jumping, upward velocity, most actions, many body interactions, and some active-window changes reject. `Guest::apply` checks the exact guest force, host connection, epoch, material tick and digest before allowing its terrain step; it is not a general client prediction or correction system. Calling ordinary `Sim::tick()` even between material ticks bypasses those checks. A real populated game normally fails the current guards immediately.

## First real-transport milestone: disposable two-player sandbox

1. Add an explicit developer-only mode with two actual local crabs in separate, disposable test-level Sims and no enemies, recorder, persistent writes, migration or live cellular game state. Keep the existing cellular co-op and save UI disabled. Negotiate an application version, static level/tuning identity, protocol version and a fresh session epoch; reject incompatible worlds, duplicate player claims and a connection that is not the selected host or the one bound to the guest. The existing `Peer` pairs player ID with actual Matchbox connection ID; use it on **every** input, checkpoint, frame and acknowledgement, not just the initial handshake. Never use a claimed player ID as authority.
2. Install a bounded host checkpoint in the guest's temporary Sim before spawning or enabling either actor. Explicitly agree on game tick, terrain tick, phase, initial positions and controls. Current `begin_guest_shared_walking` needs fresh tick zero; supporting a resumed live world requires a separately tested clock/actor restoration contract. Abort on phase, level, clock or checkpoint mismatch. Dropping the session and disconnecting must restore the real guest's private terrain via its existing `OwnWorld` lifecycle; no network data may overwrite a solo save.
3. Define a bounded, versioned **input** message distinct from an authoritative terrain `Frame`: epoch, game tick, sequence, player and the complete control state including one-shot press edges. Reject non-finite/out-of-range input, duplicate IDs, forged connections, duplicate/stale/out-of-window sequence numbers and gaps. Allow only the currently proved walking/guest-dig subset; unsupported input pauses before either Sim, clock, terrain, outbox or press edge is mutated. Cap per-peer pending bytes, packets and tick horizon; disconnect, host change, timeout, queue overflow and corrupt input invalidate the epoch and clear its buffers.
4. Replace the unconditional `simulate` path **only inside the disposable developer mode** with an explicit barrier. At each 30 Hz material boundary, both sides must be at the same 120 Hz tick with the same accepted inputs. Host validates the source-bound guest proposal against the guest actor state for that tick, derives/validates both forces, then calls the transactional guarded host step exactly once. It sends the ordered terrain frame; the guest applies it to the same pre-step terrain, verifies the digest, and acknowledges. Both sides may advance the three guarded non-material ticks only in the agreed order. Any failure after partial work must roll back the entire affected tick, including actor state, terrain, events and outbound messages, or abandon the disposable session; the current guest terrain step plus subsequent independent actor ticks do not by themselves provide that transaction. Freeze the accumulator while waiting and do not convert network delay into an unbounded catch-up burst.
5. Do not trust a guest-supplied `HostPlayerForce` merely because its `PlayerId` is correct. Today's FakeLink test forwards the guest's computed force; it does not validate position, dimensions, velocity, grounded state or action against an authoritative guest actor on the host. Either make the host simulate that actor from the tick-stamped input, or specify and test a bounded, authoritative state/force validation and reconciliation contract. The ordinary `Msg::Crab` interpolation stream cannot be the deterministic input to this step.
6. Exercise this exact app scheduling and real Matchbox transport in two isolated Chrome instances: both players walk and the guest digs across sand, mud and pebbles, including overlapping and separated bodies. Compare each terrain frame and authoritative actor state to a single reference run, preserve mass, and inject reordered, duplicate, delayed, lost, forged and oversized packets. Verify waiting, unsupported input on *each* of the four game ticks, failed sends, digest divergence, disconnect and reconnect leave no partially applied tick or altered private world. Run an additional native/Wasm determinism check; a same-process FakeLink result does not establish cross-platform equality.

This milestone is a correctness harness, not a playable release. With stop-and-wait at each material frame, network round trips directly throttle movement; the local probe's one-packet exchange took roughly 148 ms including game-loop scheduling. An eight-fragment checkpoint window improved join throughput, but does not solve 30 Hz live latency. The current host method clones a full `Sim`, the guest digest path clones and serializes the world, and active-window handling still imposes substantial per-step work. Measure CPU, frame time, queued bytes and peak total memory on actual target phones before extending scope. The developer ingress cap covers tagged probe payload only; normal Matchbox traffic, WebRTC/browser buffers, checkpoint assembly and decompression remain separate unbounded or large-memory paths. Full-world checkpoint joins are not a scalable correction strategy.

## From guarded sandbox to actual game

- **Actor authority and input:** choose a single authoritative owner per player and make remote actor state reproducible from tick-stamped controls and world state. Define how inventory, damage, interaction, animation events and one-shot controls are acknowledged and deduplicated. Preserve existing ordinary co-op semantics until the cellular path has equivalent tests.
- **Prediction and reconciliation:** keep an explicitly bounded input/state history. Predict only cases known to be reversible; attach epochs and authoritative tick/hash to confirmations. On mismatch, restore an authoritative actor and affected terrain snapshot, replay accepted local inputs and smooth presentation separately. When rollback history, chunk correction, hashes or memory budgets are unavailable, pause safely and request a bounded resynchronization or leave to the restored solo world; never silently continue divergent simulations. A malformed, stale or forged packet must not trigger arbitrary rollback or replace private state.
- **Creatures and environmental forces:** existing co-op distributes enemy ownership; the cellular path must agree on which simulation owns each creature at a given tick and propagate the resulting deterministic movement, attacks, wakes, digging, deaths and ownership changes once, in a stable order. Define handover and duplicate/late event rules and prove a moray/shrimp encounter, shared damage and substrate disturbance in a two-player reference test. Until an actor, kelp interaction, current source or environmental effect has an exact shared representation, pause or reject the session rather than omit its terrain forces.
- **World scale, joining and failure:** replace whole-world snapshot copying/digesting with validated chunk-scoped transfer and bounded, backpressured decode; retain the guest's own world across join, host migration, reconnect and cancellation. Define epoch changes and authoritative chunk repair, then test dropped/reordered chunks, host departure during transfer, mixed-host packets and memory limits. Ensure separate interest windows and their boundaries preserve deterministic ordering, particle conservation and pebble atomicity.
- **Release gate:** lift the cellular `build` guard only after actual app tests cover supported controls, NPCs, full-map saves/replay, migration, mobile networking, browser backgrounding, normal/offline recovery, and sustained CPU/memory budgets. A single developer probe or taste test is not evidence of feature parity.
